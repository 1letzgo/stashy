# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Stashy is a native iOS/tvOS/macOS SwiftUI app for browsing and managing a Stash media server (GraphQL API). Multi-server support, custom filtering, video playback, device sync, and feed-style browsing (StashTok/Feeds). Premium features are gated behind `stashy+` (StoreKit).

`android/` is a parallel native Kotlin/Compose port (phone + Android TV, one APK) that mirrors the Swift code file by file — no KMP, no shared code except the `graphql/` documents (wired in as an assets dir) and the localization keys. Features and fixes land on both platforms. `android/README.md` is the Android counterpart of this file: iOS↔Android file map, Material conventions, playback (Media3 with transcode fallback), flavors and releases — read it before touching `android/`.

```bash
xcodebuild -project stashy.xcodeproj -scheme stashy -destination 'generic/platform=iOS' build
```

### Tests
iOS: no test target is wired into the Xcode project. `stashyTests/` (Swift Testing: infrastructure, image date sort, legacy-paid stashy+) and `stashyUITests/` are files only, ready to attach to a future target. Verification = the three builds above + manual testing on device/simulator. Android has real unit tests (see above), including pure logic such as `tv/TvLogic.kt`.

## Architecture Overview

### Core Patterns

**Singleton managers** — cross-cutting state, all `.shared`:
- `AppearanceManager` — theme/tint colors, O-counter icon choice (UserDefaults)
- `ServerConfigManager` — multi-server config storage + active server
- `TabManager` — tab visibility/order, dashboard rows, reels mode config
- `KeychainManager` — API key storage (iOS only; tvOS falls back to UserDefaults)
- `GraphQLClient` — actor-based GraphQL client (async/await + completion APIs)
- `ImageCacheManager` — dual-tier image cache (memory + disk, server-scoped)
- `stashy/Managers/`: `SecurityManager` (passcode/biometric lock), `SessionTimelineLoader`, `OCountHeatmapLoader`, `StashyPlusManager` (entitlements), `AppIconManager`, `LoginAuthHelper`, `StashSyncManager` (+ `StashVideoSyncManager`), `VideoAnalysisManager`, `SubtitleController`
- Nested in `StashDBViewModel.swift`: `DownloadManager`, `HandyManager`, `ButtplugManager`, `LoveSpouseManager`; `StoreManager` lives in `Settings/SettingsView.swift`

**Navigation**: `NavigationCoordinator` is an `@EnvironmentObject` passed app-wide. Handles tab selection, deep links, navigation-stack resets (UUID-based `.id()` modifiers), cross-tab jumps (scene → performer), and remote injection of filter/sort state.

**Main ViewModel**: `StashDBViewModel` (~14k lines, `@MainActor`) is the app's data hub — server status (staggered init: Filters → Statistics → Ready), statistics, saved filters, scene metadata, O-counter with optimistic updates, plus the nested managers above. Its nested enums (`FilterMode`, `SceneSortOption`, `PerformerSortOption`, `SavedFilter`, …) are referenced throughout the UI layer, so it is a de-facto shared namespace, not just a view model.

**There are no per-domain ViewModels.** Screens either instantiate their own `StashDBViewModel` (e.g. `CatalogsView` keeps one warm for all catalog sub-tabs) or use a filter/sort controller (below).

**Repository layer** (`stashy/Repositories/`): `SceneRepository`, `PerformerRepository`, `StudioRepository`, `GalleryRepository`, `TagRepository` — thin GraphQL fetch wrappers. Coverage is partial; most fetching still lives in `StashDBViewModel`.

**Filter/sort controllers** (`DetailLinkedCatalogControllers.swift`): `DetailLinkedPerformersFilterModel`, `DetailLinkedImagesFilterModel`, etc. — `ObservableObject`s holding live-filter chips, sort option, saved filter, and local presets for a *scope* (`.catalogRoot`, `.studio(id)`, `.tag(id)`, `.performer(id)`, …). Hosted by the parent view so state survives child remounts. Shared preset/chip encodings live in `ListCatalogFilterSortModels.swift`; the sheets in `ListCatalogFilterSortSheets.swift`.

**Filtering**: every catalog Settings sheet (`ListCatalogFilterSortSheets.swift`, `SceneLiveFilterSheet` in `ScenesView.swift`) edits a `FilterCriteriaDocument` directly — pinned default rows, the full criteria editor below them, and on top a compact "Name or regex" field (`CatalogNameRegexSearchCard`, a `(?i)` `MATCHES_REGEX` criterion on `name`/`title`, hidden for markers). The document drives the fetch, the FAB/chrome active dot, Reset and Save. The old chip layer is vestigial: `activeLiveFilterDict` returns `[:]` in most lists (markers still keep scene chips).
- Where the state lives: detail tabs host it in their `DetailLinked*FilterModel` / `ScenesListFilterMemory`; Home sub-tab lists get theirs from `CatalogRootFilterMemories` in `CatalogsView.swift` (one `CatalogListFilterMemory` per list: shared document + a snapshot of sort / saved filter / preset / search restored in the list's `init`; Images use `DetailLinkedImagesFilterModel(.catalogRoot)`), so a sub-tab switch keeps list, dot and sheet consistent. Cleared on `"ServerConfigChanged"`. Standalone tab variants pass no memory and keep local state.
- `stashy/Filters/` holds the advanced editor, mirroring Stash's own model: `FilterCriterionTypes.swift` (`CriterionModifier` + criterion kinds and their default payloads), `FilterFieldCatalog.swift` (per-`FilterMode` field descriptors), `FilterCriteriaDocument.swift` (an editable `object_filter` with sanitizing), `FilterCriteriaEditorView.swift` (one row per criterion kind), `CatalogQuickFilters.swift` (`CatalogFilterCriteriaBody`: quick chips plus the collapsible "Advanced criteria" editor in every filter sheet), `FilterPickerOptionsStore.swift` (shared, cached studio/tag/group/performer options — never create a `StashDBViewModel` per criterion row), and `FiltersToolsView.swift` (Tools → Filters).
- Merge rule (`FilterCriteriaDocument.merged(with:)`): the document is the base, any chip fragment is layered on top and wins for its own key.
- Selecting a server filter loads its criteria into the document (`loadCriteriaDocument(from:)`), and the fetch then passes `filter: fetchBaseFilter` — `nil` while the document holds the copy, the filter itself while the document is still empty. Without that, the server filter would resurrect criteria the user just edited away.
- The advanced editor commits on `Done`, never per keystroke; text fields commit on submit/focus loss. Never wire `onChange:` of a criterion row straight to a refetch.
- Adding a new filterable field = add a `FilterFieldDescriptor` to the right catalog array and make sure its kind serializes to the shape Stash's `*FilterType` expects (`GenderCriterionInput` uses `value_list`, `duplicated` is `PHashDuplicationCriterionInput`, …).
- Saving goes through `StashDBViewModel.saveFullObjectFilter` (preserves `ui_options.stashy.liveFragment` unless explicitly replaced); renaming goes through `renameSavedFilter`, which never rewrites criteria.

**Pagination**: `stashy/Utilities/PaginatedLoader.swift` — generic `PaginatedLoader<T>` with `loadInitial()`, `loadMore()`, `refresh()`, `reset()` and per-type static builders. Currently unreferenced by app code; treat as available infrastructure, not the established pattern.

### Data Flow

1. **Network**: `GraphQLClient`
   - Actor-based for thread safety
   - Shared `StashTrustDelegate` (GraphQLClient.swift) accepts self-signed certs only for local hosts (localhost, `.local`, private IPv4, Tailscale 100.64/10, private/link-local IPv6); used by GraphQLClient, ImageCacheManager, `StashNetworking.session` and the download session
   - `withDatabaseRetry` auto-retries "database is locked" (execute, executeRaw, performMutation)
   - Typed envelope validation: errors with null data are fatal, partial errors tolerated
   - Requests outside GraphQLClient use `stashRequest(to:config:)` + `StashNetworking.session`
2. **Logging**: `AppLog.debug` / `AppLog.error` (SharedUtilities.swift) gate output behind DEBUG; `AppLog.redacted` masks secrets. Never use raw `print()` or log API keys.
3. **Image loading**: `ImageCacheManager` — memory 300 MB / 300 items, disk files older than 7 days are cleaned up (every 4 h), scoped per server ID (prevents leakage on server switch). Cache keys strip timestamp params but keep `width`/`height`/`size`. Use `CustomAsyncImage`. Cleanup every 4h.
4. **GraphQL queries**: two coexisting sources
   - `.graphql` files in `graphql/` (folder reference — new files are picked up automatically), loaded via `GraphQLQueries.loadQuery(named:)` / `queryWithFragments(...)` (thread-safe caching), with `fragment_*.graphql` for reusable field sets
   - Inline `static let` mutation/query constants in `GraphQLQueries.swift` (~38 extracted from StashDBViewModel)
5. **Server config**: `ServerConfig` (Codable, UserDefaults) — name, address, port, protocol. API keys in Keychain on iOS. Server-specific settings use the `"<key>_<serverID>"` suffix pattern. Switching servers clears URLCache + image disk cache, posts `"ServerConfigChanged"`, and ViewModels call `GraphQLClient.shared.cancelAllRequests()`.

### Platform Differences

Shared code with `#if !os(tvOS)` guards. Many iOS-only files guard their *entire* contents, so a new iOS-only file still compiles into the tvOS target harmlessly — but tvOS UI is a separate hand-written surface in `stashyTV/` (`TV*` views, focus-based navigation, remote input, simplified layouts). tvOS lacks Keychain, haptics, UIKit scene delegates, and gesture-heavy components.

**iPhone Duo** (foldable, iOS 27.1+; outer 466×678 pt; inner 951×669 pt with a vertical fold in the usual hold, 669×951 turned, regular in both dimensions) runs the iOS target and switches size live. Device Hub folds the simulator (Closed / Partially Open / Open). The inner display turns with the device but ignores `requestGeometryUpdate`. Take size from the view's own container (`onGeometryChange`, `GeometryReader`), never `UIScreen.main`, and shape from width against height, never orientation or `userInterfaceIdiom`. Regular width no longer means iPad. Bars can stand vertically along a side, so a bottom overlap can be 0 and left/right insets can differ. A size changes every animation frame during a resize: don't put it in `@State` of a heavy view (`LiveSizeBox` in `ReelsView.swift`). The fold is 40 pt wide and `FoldLayout.swift` exposes it: `GeometryProxy.foldRegion` (nil without a fold or when a view lies on one side; the system reports it inactive while lying flat, so it queries inactive regions too) and `observesHalfOpenHinge`. Users: `MagazineReaderView` (one page each side), `SceneDetailView` / `PerformerDetailView` / `StudioDetailView` (two columns around a vertical fold), `ScenesView` (plain list only: list left, `SceneDetailView` in a column right, which becomes a pushed page when the phone folds), `AetherSceneSurface` (tabletop: fold across and half open).

**macOS** (`stashyMac`, macOS 26, same bundle ID `de.letzgo.stashy` for universal purchase) compiles the *same* sources as the iOS target plus `stashyMac/` (filesystem-synchronized: `StashyMacApp.swift` entry point + menu commands, `MacCompat.swift`, `MacAppIcon`). Mac Catalyst is not an option: AetherEngine's FFmpeg/Dovi xcframeworks ship no Catalyst slice.
- `MacCompat.swift` aliases `UIImage`/`UIColor`/`UIFont`/`UIResponder` to AppKit and shims the UIKit surface the shared code touches (`UIApplication`, `UIScreen`, `UIDevice`, `UIGraphicsImageRenderer`, iOS-only SwiftUI modifiers like `navigationBarTitleDisplayMode`, `keyboardType`, `.navigationBar`/`.tabBar` placements, `editMode`). Extend it rather than sprinkling `#if` when a new shared file uses such an API.
- Real behavioural differences go behind `#if os(iOS)` / `#if os(macOS)` at the call site (AVAudioSession, orientation, UIKit nav-controller hacks, `PlayerMenuButton` = `NSMenu`, `ZoomableScrollView`, `AnimatedWebView`, paging TabViews → paging `ScrollView`/plain switch). Note `#if !os(tvOS)` now also means macOS.
- Sandbox entitlements (`stashyMac.entitlements`) the app depends on: `network.server` — AetherEngine serves the original file to AVPlayer through a loopback HTTP server (`HLSLocalServer`); without it every original falls back to the server transcode / "No playable source". `keychain-access-groups` — the data-protection keychain (`KeychainManager`) silently fails without it.
- New shared iOS files must be added to the `stashyMac` Sources phase too (same 4 pbxproj sections, plus the Mac target's Sources list).

`SwiftDraw` (SPM) is linked to **all three** targets. Every studio image (PNG/JPG/SVG) goes through `StudioLogoStore` (`stashy/StudioLogoStore.swift`: fetch → SwiftDraw raster → alpha trim → memory + disk cache). Never render an SVG live in a `WKWebView` or per-card.

## Key Components

- **Tabs**: `AppTab` enum in `TabManager.swift` (dashboard, catalogue, scenes, images, galleries, performers, studios, tags, groups, markers, media, reels, stashline, downloads, tools, stashyPlus, search, settings). Visibility/order configurable. `catalogue` ("Home") hosts sub-tabs via `CatalogsView.CatalogsTab`.
- **Home/Dashboard**: `stashy/Home/` — `HomeRowView`, `HomeSceneCardView`, `HomeStatisticsRowView`, `HomeChannelsRowView`; rows configured in `Settings/DashboardSettingsView.swift`. Besides the shipped rows a user adds own rows there ("Add Row": Filter or Sort, kind Scenes / Performers / Studios / Galleries, then a saved filter or one of the kind's sort options; a sort row has `sortRaw` and no `filterId`): `HomeRowType.customFilter` with `filterMode` + `filterId` on `HomeRowConfig`, fetched with the filter's criteria and its own sort (`fetchCustomFilterHomeRow`), cached per row id (`HomeRowConfig.storeKey`). The title opens the list with the filter and its sort applied (`NavigationCoordinator.activeFilter`, each list takes only a filter of its own mode). Ten former rows are retired (`HomeRowType.isRetired`): an enabled one keeps working, a disabled one is dropped on save. iOS and macOS only (not tvOS, not Android yet). Live without a refresh: scene rows patch in place (`sceneLiveUpdates`), For You and Forgotten Favorites apply the same scene notifications to the cards they show (`SceneLiveChange`, no rebuild or reorder), performer / studio / gallery rows reload in place after `<Entity>Updated` (posted by the edit functions in `StashDBViewModel`, next to the `<Entity>Deleted` ones) and Statistics refetch 1.5 s after a delete, play or O count. Pull to refresh runs its work in an unstructured task: the rows publish at once and SwiftUI cancels the `.refreshable` task on a view update. The hero backdrop is scroll content and would cover the refresh control, so `RefreshControlOnTop` lifts it. The Last Played row has a line below each card (when it was played, and a ··· menu: "Mark as Finished", "Remove from Last Played"). Removing only hides the scene in this row, on the device (`LastPlayedHiddenStore` in `SharedUtilities.swift`, `last_played_hidden_<serverID>`: scene id → time hidden); nothing on the server changes, the Scenes list sorted by Last Played stays complete, and the scene returns with its next play (`ScenePlayAdded`, or a later `last_played_at`). The row fetches as many more scenes as are hidden. Android: `data/LastPlayedHidden.kt`, same key.
- **Tools tab** (`ToolsView` in `MainTabView.swift`): dispatches to `OCountHeatmapToolsView`, `SessionTimelineToolsView`, `FiltersToolsView`, `HotOrNotToolsView` (Match), `RateMeToolsView`, `TopListsToolsView`. When stashy+ is locked, the `stashyPlus` paywall tab replaces `tools`. Home and Tools show their sections as a dropdown in the top row (`HomeViewsMenu`, `ToolsBreadcrumbRow.toolMenu`; a neutral pill "Dashboard" / "Tools" on the start page, tinted with the section's name inside one). Downloads and the Watchlist are no tools any more: with stashy+ the Dashboard's top row carries a Downloads button (pushes `DownloadsView`) and, with the mini player on, a Watchlist button left of it (`MiniPlayerStore.openWatchlist()`, opens Now Playing); the scene page has the watchlist toggle as a slot in its top bar, left of Download.
- **Magazin** (`MagazineListView`, a Home sub-tab shown only when switched on in Settings › stashy+ (`MagazineMode.enabledKey`), with its default filter there; Settings › Home Tabs offers the same switch and filter and sorts it with the other tabs; same on Android): the regular `GalleriesView` list through `GalleryListHost` as portrait covers, read as two-page spreads in `MagazineReaderView`; pages sorted client-side in natural file order, double-sided page curl on iOS, paging scroll view on macOS; last read page in `MagazineReadingStore`, a local copy merged with gallery `custom_fields` `stashy_read_page` / `stashy_read_at`, newest wins; go-to-page sheet with Stash gallery chapters and a details sheet; iOS, macOS and Android, not tvOS. Tap to translate (fullscreen page only, switched on in Settings › stashy+ › Magazin with its translation language below, `magazine_translate_text`): the page's text is recognized on the device (`MagazineTextRecognizer`: Vision `RecognizeDocumentsRequest` from iOS 26, which reads vertical Japanese / Chinese, `VNRecognizeTextRequest` before; Android ML Kit with bundled Japanese / Chinese / Korean models), lines are merged into bubbles and outlined, a tap on one shows its translation in a card (`MagazinePageTranslation`, the caption translator and the subtitle language as target). `ZoomableScrollView.onContentTap` / Android `ZoomableBox.onTapAt` give the tap in the content's own coordinates; on iOS the content lies inside the hosting view's safe area. The Simulator has no Translation framework.
- **Feeds / StashTok** (`ReelsView.swift`, ~7.5k lines): modes Scenes / Markers / Clips, infinite scroll via `ScrollViewReader`, per-mode sorts, mute tied to headphone detection, full-screen zoom + rotation. A performer / tag / studio handed over from a detail page stands alone: no Settings default filter is added, also not on a mode switch (it returns once the criterion is removed). Known fragility: autoplay/selection races around `currentVisibleSceneId` and `autoSelectFirstItem` — change with care. Feeds › Scenes and markers: the title link hands the live playhead to the scene page, which continues there (`titleLinkScene(livePosition:)`; the saved resume point lags up to 10 s and is missing before the scene counts as played). The time bar shows the scene's markers as dots (`ScrubberState.markerSeconds` from `FeedsMarkerTimes`, filled when `findScenesFeed` is decoded, kept by scene id because `Scene`'s copy-constructors drop feed-only fields). Two switches in Settings › Playback › Feeds: `feedsAddMarkerButton` ("Add Marker" beside the rating, opens `AddMarkerSheet` without an engine) and `feedsDoubleTapMarkers` (double tap on the outer thirds goes to the previous / next marker, seconds only when there is none that way). Android: `FeedsConfig`, `FeedsMarkerTimes` in `FeedsScreen.kt`.
- **Reels feeds data**: initial fetches are single-flight (`*InitialInflightKey` in StashDBViewModel); paging has safety valves (failure streaks, no-progress detection, preview chase cap, restore budget in ReelsView).
- **Group detail** (`GroupDetailView` in `CatalogsView.swift`, Android `GroupDetailScreen.kt`): besides Scenes / Galleries / … a "Groups" section lists the direct sub-groups (groups query with `containing_groups = this group`, depth 0, into the page's own `viewModel.groups`), shown from one sub-group on; a group with only sub-groups opens on it. The header footer links the containing groups ("In: …"). So groups nest like folders (1letzgo/stashy#19). Not on tvOS.
- **Scene detail**: `SceneDetailView.swift` + `stashy/SceneDetail/Components/` (`SceneVideoPlayerCard`, `SceneHeatmapCard`, `ScenePerformersStudioCard` (in `ScenePerformersCard.swift`; studio + performers row, also used by the opened gallery), `SceneTagsCard`, `SceneGalleriesCard`, `SceneGroupsCard`). With the mini player on, the page still plays inline and hands a playing engine to the bar when it is left (`playsInNowPlaying` is off, an experiment; the old expression is in its comment). A pinned player gets an explicit width (full width, at most 60 % of the height for the picture): left to the stack it shrinks to a small box on an iPad. Landscape (`usesSideInfoColumn`, from the container's size): the player stays on the left and every card scrolls in a column on the right, about a third wide; on a wide container (iPad sideways, 900 pt and up) always, on a phone in landscape as an experiment (`phoneLandscapeSideColumn`), where the picture is sized to the height and the column gets the rest. `AetherSceneSurface` takes its compact controls for a surface under 260 pt high or under 600 pt wide. A scene with a resume point shows Resume, Start from beginning and "Mark as Finished" on its cover: the last drops the resume point (`StashDBViewModel.markSceneFinished`: `sceneSaveActivity` with `resume_time: 0`, optimistic, `SceneResumeTimeUpdated` for the lists, runs with Track activity off too) and never adds a play, since plays count from watched time. The play count pill is a menu with the same action and "Remove from Last Played" / "Show in Last Played Again".
- **Video playback** (`stashy/Playback/`): every surface on iOS and tvOS runs on `AetherSceneEngine` (AetherEngine SPM package) — there is no AVPlayer path and no quality selection; playback always uses the original file (`paths.stream`, or the local download). `AetherSceneSurface` is the full transport surface (PiP + AirPlay on iOS), `AetherVideoSurface` the bare video layer, `AetherPreviewPlayer`/`AetherPreviewSurface` (+ `AetherPreviewPool`, max 2 engines) the muted card previews, `LocalDownloadStore` the single lookup for downloaded files (the download store is per server, `Documents/Downloads/<serverID>/`, since Stash ids repeat across servers).
- **Subtitles / transcription** (`stashy/Subtitles/`): live on-device transcription + translation (`SceneLiveTranscriptionController`, `SceneCaptionTranslator`). Audio reaches the recognizer via `AVAssetReader` on the original when it is byte-range readable, otherwise via an audio-only Stash transcode fetched ahead of the playhead (`SceneTranscodeAudioPrefetcher`, captions only — playback never transcodes), and only as a last resort via the engine's shared PCM tap (realtime drafts, visibly less stable).
- **For You** (`Managers/SceneRecommendationEngine.swift`, Home row `HomeRecommendationsRowView`, settings `RecommendationSettingsView` under Settings › stashy+ › Recommendations): stashy+ and shown only while its own switch (`isEnabled`, `recommendations_enabled`) and Tag Suggestions or Similar Scenes are on (`isFeatureOn`); as the first scene row it is the Home hero. Its title opens Scenes with the sort `SceneSortOption.forYou` ("For You", Android raw `forYou` / field `for_you`): `loadScenesPage` answers it from the engine (up to `listLimit` 25, one page, search by title, filters ignored); `sortField` stays `random` so no server ever sees it, and Home rows, Feeds and saved-filter sorts never offer it (`generalCases`). The row shows the first `count`; Balanced also fetches played-before candidates and alternates new and played picks. Runs only on device data: the Suggestions statistics build also writes a per-scene index (`LocalSceneIndex`, `AITagStats/<key>.scenes.json`: tag / performer / studio ids, plays, O count, rating, last played, plus the scene's `SceneListFields` for its card), and `buildLocal` scores the whole library from it without a server request; until the first build the row shows "Getting your library ready…" and fills when the build finishes. Plays from this app go into the index at once (`noteLocalPlay`); plays elsewhere arrive with the next build (12 h). Similar Scenes ranks from the same index on iOS/macOS/Android (`rankLocal`); Apple TV keeps its server query. Builds a taste profile from scenes played in the look-back window (recency, replays, `o_history`, completion, rating; tags weighted by rarity), fetches candidates per top performer / studio / tag plus unplayed scenes close to the most-watched single scenes, scores them with the user's weights and picks diverse ones; the strongest factor is the card's reason. Random order is seeded anew for every build and the last 3 lists (`recommendations_last_picks_<serverID>`, device-local) are pushed back. After every list shown the next one is built in the background and kept in `Application Support/ForYou/<serverID>.json` (tied to the settings, max 36 h), so app start, pull to refresh and Refresh show it at once (pull to refresh waits for the list). Balanced weighs never-played and not-played-in-window the same. Per-item adjustments (`RecommendationAdjustment`, per server `recommendations_adjustments_<serverID>`, JSON): a performer, studio or tag gets a factor 0–3 (0 = hidden: its scenes never come and it learns nothing from the history; the scene score is multiplied by the factors of its items, clamped 0.05–8; above 1 also puts it into the profile so new scenes come). Set in Settings › For You › Adjustments (add via sheet) or the ··· menu below a For You card (the card's long press is the preview). Applies to For You only. Android: `data/tools/SceneRecommendations.kt`, `RecommendationsRow` in `DashboardScreen.kt`, `ui/tools/aitags/RecommendationSettingsScreen.kt` (same keys). Adjustments: `ui/tools/aitags/RecommendationAdjustmentsScreen.kt`, `RecommendationAdjust` in `SceneRecommendations.kt`.
- **Forgotten Favorites** (`Managers/ForgottenFavoritesEngine.swift`, Home row `HomeForgottenFavoritesRowView`, settings `ForgottenFavoritesSettingsView` under Settings › stashy+ › Recommendations; HomeRowType `.forgottenFavorites`): stashy+, own switch (`forgotten_favorites_enabled`) plus Tag Suggestions or Similar Scenes. From `LocalSceneIndex` only: the top N (`forgotten_favorites_pool` 10/25/50/100) by plays, O-Count or both (`forgotten_favorites_ranking`), minus scenes played within `forgotten_favorites_days` (30–365), shown in fewer of the last lists first and random within each group, at most 20 cards. No title link; an empty row is left out of Home. Rebuilds on pull to refresh and on a settings change, otherwise stays for the session. Android: `data/tools/ForgottenFavorites.kt`, `ForgottenFavoritesRow` in `DashboardScreen.kt`, `ui/tools/aitags/ForgottenFavoritesSettingsScreen.kt` (same keys).
- **Device sync**: `StashSyncManager` ("AI Motion", stashy+ only) drives haptic/device channels from on-device video analysis (`VideoAnalysisManager`); intensity is published through Combine subjects, deliberately **not** `@Published`, to avoid ~30 Hz SwiftUI rebuilds that restack the video layer over menus. Plus `HandyManager`, `ButtplugManager` (Intiface/funscript), `LoveSpouseManager`.
- **iCloud settings sync** (`Settings/ICloudSettingsSync.swift`, off by default, per device; iOS and macOS only): servers and the keys `SettingsTransfer.isSyncable` allows go through `NSUbiquitousKeyValueStore`, one entry each, merged three-way (`ICloudSettingsMerge`) against a hash file in Application Support. An empty store never deletes anything, only explicit deletion markers do. API keys and custom headers never enter that store: `KeychainManager` keeps a synchronizable copy (iCloud Keychain) beside the device-only item. A setting that changes constantly or belongs to one device must be added to `deviceLocalPrefixes`.
- **stashy+ gating**: `StashyPlusManager.isUnlockedNow` / product IDs in `Managers/StashyPlusManager.swift`. Subscriptions + lifetime IAP + legacy paid purchase unlock; tips never do. Gate new premium features through this manager, never an ad-hoc flag.
- **Chrome**: `FloatingCatalogBar.swift` (`FloatingActionBar`, `CatalogFloatingChromeState` — floating bar hides when no server or empty-list-with-error), `StashyTopNavStrip.swift`, `SharedChromeComponents.swift`.
- **Design system**: `DesignTokens.swift` (spacing, corner radius `DesignTokens.CornerRadius.card` = 12pt, shadows, animation presets, `DesignTokens.Chrome.*`), view extensions `.cardShadow()` / `.subtleShadow()` / `.floatingShadow()`, `HapticManager`, `ToastManager`.
- **Card count badge**: a performer, studio, tag or group card shows one count top right: the count its list is sorted by, the scene count for every other sort (`PerformerBadgeType.forSort`, `CatalogCardBadge(sortField:)` in `SharedUtilities.swift`; Android `CatalogCardBadge` in `Sorting.kt`). A count the model lacks falls back to scenes. Catalog lists, the linked tabs of detail pages and Home custom rows pass their sort; a new list of such cards must too.
- **Sub-studios**: two app settings, not filter criteria (`StudioCountsStore` in `StudioRepository.swift`; Android `data/SubStudios.kt`, `StudioCountsStore`): "Hide sub-studios" (`studios_hide_sub_studios`) adds `parents IS_NULL` to the Studios list (not while searching, not over a `parents` criterion of the user's) and switches the second one on with it; "Include sub-studio content" (`studio_counts_include_sub_studios`, the former counts switch) makes every `studios` scope of a studio's page, the Feeds handover and the studio bulk download use `depth: -1` (`StudioCountsStore.contentDepth`) and the cards count with depth. Both sit in the Studios settings sheet (`SubStudioOptionsCard`) and in Settings › Home Tabs; a studio's page sets `\.showsSubStudioContentOption`, so every filter sheet opened from it shows the content switch (`CatalogFilterCriteriaBody`). The lists watch the keys and refetch. `StudioFields` carries `parent_studio` / `child_studios`: the card shows the sub-studio count top left and "Part of …" at the bottom, the page links its parent. Counts with depth come from `findStudioCounts` (0.32+, with O Count) or `findStudioCountsBasic`. Stash sorts `scenes_count` by a studio's own scenes, so with the content switch on that sort fetches the whole list once (`findStudiosWithSceneCountAll`, `per_page: -1`) and sorts it in the app. Edit Studio has "Parent Studio": the studio picker in its parent mode (`excludedStudioId`: every studio by name, sub-studio counts), written at once; `StudioParentChanged` (Android `LibraryEvent.StudioParentChanged`) makes the Studios list and open sub-studio tabs reload. Stash's `StudioFilterType` knows `parents`, not `parent_id`, and `TagFilterType` has no `studios` (a studio's tags go through `scenes_filter`).
- **Sub-tags**: the tag counterpart of the sub-studio switches (`TagHierarchy` in `TagRepository.swift`; Android `data/SubTags.kt`, `TagHierarchyStore`): "Hide sub-tags" (`tags_hide_sub_tags`) adds `parent_count = 0` to the Tags list, "Include sub-tag content" (`tags_include_sub_tag_content`) makes the `tags` scopes of a tag's page, the Feeds handover and the scene bulk download use `depth: -1` (the tag image download stays at 0). A tag can have several parents: `findTags` / `findTag` return `parents { id name }` and `child_count` (not `TagFields`, scenes use that fragment), the card shows the sub-tag count and "Part of X +2", the page links every parent and has a "Sub-Tags" section (`fetchDetailTags(parentTagId:)`), Edit Tag picks the parents in `ParentTagsPickerSheet` and writes them at once (`TagParentsChanged` reloads the lists). With the content switch on `GraphQLQueries.tagQuery` adds the five `…_count_all` aliases for the cards, and the scene count sort fetches the whole list and sorts it in the app. Sheets: `SubTagOptionsCard`, `\.showsSubTagContentOption`. A sort card of a settings sheet wraps onto two rows when its sort name is long (`ViewThatFits`).
- **Image viewing options** (`ImageScalingMode`, `ImageBackdropMode`, `ImageBackdrop`, `ImageAverageColorStore` at the end of `SharedUtilities.swift`; Android `data/ImageViewing.kt`): four settings in the Images settings sheet (`ImagesFeedAutoplaySettingsCard`; Apple TV: Settings › Images). `images_fullscreen_scaling` (`fit` / `fill` / `auto`; nothing stored reads the former `images_fullscreen_immersive`, Apple TV defaults to `fit`) for the fullscreen viewer, the Apple TV viewer and slideshow; `images_background` (`black` / `match` = the thumbnail's average colour, once per URL) behind an image that does not cover its space; `images_grid_fit` shows the whole image on every image card (`ImageThumbnailCard`); `images_fullscreen_keep_rating` keeps the O Count and rating pills when a tap hides the fullscreen chrome (the other parts fade but keep their place). Apple TV and Android TV: a click in the viewer opens rating and "Add O". Feeds › Clips shows the same media and follows the same three settings for clip items (scaling instead of the Feeds fill switch, background, rating pills; `ReelItemView.clipImage`, Android `FeedRow`). A video's surface is black, so a fitted video is framed to its picture's aspect ratio (`fittedToAspectRatio`) and the background shows around it.
- **Scene edit** (`EditSceneTitleSheet` in `SceneVideoPlayerCard.swift`, Android `SceneSheets.kt`): "Normalize" under title and description turns a file name into a title (`SceneTitleNormalizer`, same rules on Android) and shows only while it would change the text. The performer hero lists all `urls` when expanded (own small query, not in the list fragment).
- **Chrome on scroll**: dragging a catalog list hides the section strip and quick bar, and scrolling up or reaching the top returns them (`CatalogChromeCollapse`, `collapsesCatalogChrome` on the list's scroll view, `catalogPinnedQuickBar` for the bar). Feeds uses the same fade and slide (`StashyChromeAutoHide`); paged Feeds modes return on a tap, Pics follows the catalog behaviour. Opacity and offset only: animating chrome height relays out the list and the changed inset reads as a scroll, which froze Home in a loop. `isCollapsed` publishes one run loop after the scroll update, because published inside it the chrome jumps in a single frame and the animation never runs.
- **Accent and accessibility**: text or icons on a fill of the accent colour use `Color.onAppTint` (white or black by luminance), never a literal `.white`. All chrome goes through `stashyGlass`, which answers Reduce Transparency and Increase Contrast and limits its text to xxLarge. Text sits at 11 pt or larger; text on a fixed-size image or cover gets a `.dynamicTypeSize(...)` limit.

## Important Patterns

### Adding/Removing Files
The `stashy` target uses classic Xcode groups — update `project.pbxproj` in 4 sections (`PBXBuildFile`, `PBXFileReference`, `PBXGroup`, `PBXSourcesBuildPhase`). The `stashyTV` target uses a filesystem-synchronized group (auto-pickup). `graphql/` is a folder reference.

### Adding a New Setting
1. Define the UserDefaults key (use the `_<serverID>` suffix if server-specific)
2. Add UI in the matching section under `stashy/Settings/`
3. Update the owning singleton (`TabManager`, `AppearanceManager`, …) if one exists
4. Decide whether it must reset on `"ServerConfigChanged"`
5. Settings export and iCloud sync pick it up automatically; exclude it in `SettingsTransfer` if it must stay on the device

### Adding a New GraphQL Query
1. Add a `.graphql` file to `graphql/` (folder reference — no pbxproj edit needed)
2. Load via `GraphQLQueries.loadQuery(named:)` or `queryWithFragments(...)`
3. Put the fetch in the relevant Repository when one exists

### Supporting a New Content Type
1. Codable model (models mostly live in `StashDBViewModel.swift` / `SharedUtilities.swift`)
2. Repository in `stashy/Repositories/`
3. View in `stashy/`, plus a `DetailLinked*FilterModel` if it needs filter/sort
4. `AppTab` / `CatalogsTab` entry in `TabManager.swift` / `CatalogsView.swift` if it needs a tab
5. GraphQL queries + fragments, and `FilterFieldCatalog` fields if it should be filterable

### Notifications
- `"ServerConfigChanged"` — server switched, reset all data
- `"AuthError401"` — posted by GraphQLClient on 401
- Background URL session completion (downloads)

### UserDefaults Keys
- Active server: `"stashy_server_config"`; server list: `"stashy_saved_servers"`
- Per-server: `"<key>_<serverID>"` (dashboard rows, tab visibility, …)
- Tint: `kTintColorRed`, `kTintColorGreen`, `kTintColorBlue`, `kTintColorAlpha`

## Localization
Every UI text has one key shared by iOS / tvOS / macOS and Android: Swift `tr("play_count")`, Kotlin `tr(R.string.play_count)`, values as extra arguments (`tr("arg_scenes", count)`, always formatted as text). English lives in `android/app/src/main/res/values/strings.xml`; `tools/l10n/sync_en.py` copies it into `stashy/Localizable.xcstrings`. Translations come from Tolgee (https://tolgee.shelf.am, project "stashy", id 2) via `tools/l10n/tolgee.sh push|pull` (needs `TOLGEE_API_KEY`). Details: `tools/l10n/README.md`.
- A new UI text gets a key in `values/strings.xml` and `tr(...)` on both platforms; then `sync_en.py`. Never a bare literal in `Text(...)` for UI. Key names follow the role prefixes in `tools/l10n/README.md` (`action_`, `confirm_`, `error_`, `loading_`, `empty_`, `placeholder_`, `hint_`; Stash terms keep Stash's key). Reuse the key when the English is the same; never compose a text from several keys; symbols and upper-casing go in code.
- Never `tr()` for data: UserDefaults keys, raw values, ids, comparisons, file names, HTTP bodies, GraphQL, logs. Enums whose `rawValue` is persisted stay literal and get a separate display property that calls `tr`.
- Wording follows Stash's own UI (US spelling): `localization/glossary.csv`. "O Count", "Play Count", "Groups", "API key" …
- Enum labels are read on use, never stored: Swift enums get a `title` next to the persisted `rawValue`; a Kotlin enum constant takes a `@StringRes` id (or `UiText` when some constants are fixed text such as "RateMe") with a computed property, because `tr(...)` in a constructor freezes the text when the class loads. Protocol and JSON keys (Buttplug `"Ok"` / `"Error"`) stay literals.
- Language: a picker in Settings and the setup wizard (`AppLanguage`, `app_language` = `system` or a language code). Default is `system` ("Device Language"): the device's language when stashy has it, English otherwise; nothing stored counts as `system`. iOS / macOS switch in place, Android restarts.
- Apple TV stays English (no switch). Arabic is not shipped: no right-to-left layout yet.
- `SWIFT_EMIT_LOC_STRINGS = NO`: Xcode must not add extracted literals to the catalog; the catalog only holds Tolgee keys.

## Server Versions
`StashServerCapabilities` (`ServerConfig.swift`; Android `ServerCapabilities` in `ServerConnection.kt`) stores the Stash version per server. Stash rejects a whole query over one unknown field or sort, so anything newer than the oldest supported server stays behind `supports032` (or a later check): give it its own `.graphql` query instead of extending a shared fragment, and mark sort options with `requiresStash032` (their `sortField` then falls back on older servers; menus use `availableCases`). Unknown version = off. Stash 0.32+ extras living apart from the fragments: `SceneProductionDate` and `StudioCountsStore` (one batched query for all visible studios).

## Local and Regular Address
A server can carry a second, local address (`ServerConfig.localURL`, a full base URL; Android the same field). `ServerEndpointSelector` (`ServerConfig.swift`; Android `data/ServerEndpointSelector.kt`) asks it whether it is Stash and `baseURL` then returns it, otherwise `externalBaseURL`: by reachability, never by Wi-Fi name (no location permission). Probes: app start, server change and network change (GraphQL requests wait for those, `settle`, max. 2 s), quietly on becoming active and after a connection error. A change of address is not a server change: no `ServerConfigChanged`, same id, key, headers, caches. Stash answers with absolute URLs for the host a request came through, so a kept URL may name the other address: `activeAddressed` moves it where it is requested (`signedURL`, `authenticatedStashRequest`, downloads; Android the OkHttp interceptor in `Net.kt`), and the image cache key always uses the regular address. A new request built from a stored URL must go through one of these. Compare servers by `externalBaseURL`, not `baseURL`.

## SSL and Local Servers
`StashTrustDelegate.acceptsSelfSigned` decides which hosts may present a self-signed certificate: localhost, `.local`, private IPv4 ranges, Tailscale's 100.64.0.0/10 and private / link-local IPv6. No public domain is whitelisted; every other host gets standard TLS validation.

## Migration and Backward Compatibility
`ServerConfig` decodes the legacy format (connectionType, ipAddress, domain, useHTTPS) and migrates to the unified one (serverAddress, port, serverProtocol). API keys auto-migrate from UserDefaults to Keychain on iOS.
